# Guidelines

- Write tests before building the implementation.
- Start a new task in a new session — don't let unrelated work pile up in one conversation, use /handoff to make a summary of the work when a task that has knowledge which needs to be inherited to the next task is completed
- After every code write/edit, say in one short, plain-language sentence what changed and why — as if explaining it to a non-technical person.
